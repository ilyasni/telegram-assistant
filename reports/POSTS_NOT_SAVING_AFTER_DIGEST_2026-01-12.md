# Диагностика: Посты не появляются после доработок с дайджестом

**Дата**: 2026-01-12 20:40 UTC  
**Проблема**: Посты не появляются после доработок с дайджестом канала  
**Context7**: Диагностика с использованием best practices

---

## Context

Пользователь сообщает, что посты не появляются после доработок с дайджестом канала сегодня. Ранее все работало.

---

## 1. Анализ проблемы

### 1.1. Проверка постов в БД

**Результат**: 0 постов за последний час
```sql
SELECT COUNT(*) FROM posts WHERE created_at > NOW() - INTERVAL '1 hour';
-- Результат: 0
```

### 1.2. Анализ логов парсера

**Ключевые проблемы**:

1. **FloodWait от Telegram API**:
   ```
   "FloodWait when getting entity by username"
   "wait_seconds": 300, "error_seconds": 9574
   ```
   - FloodWait: 9574 секунд (~2.7 часа)
   - Причина: `ResolveUsernameRequest` (попытка получить entity канала по username)

2. **Entity not found после FloodWait**:
   ```
   "Failed to get entity by tg_channel_id after FloodWait"
   "Could not find the input entity for PeerChannel"
   ```
   - После FloodWait парсер пытается использовать `tg_channel_id`
   - Entity не найден (канал недоступен или `tg_channel_id` неверен)

3. **messages_processed = 0**:
   ```
   "messages_processed": 0, "status": "ok"
   ```
   - Парсер запускается (`CHANNEL_PARSE_START`, `CHANNEL_PARSE_END`)
   - Но не обрабатывает сообщения (`messages_processed = 0`)
   - Посты не сохраняются в БД

4. **Нет вызовов save_batch_atomic**:
   - В логах нет вызовов `save_batch_atomic` или `AtomicDBSaver`
   - Это означает, что парсер не доходит до сохранения постов
   - Причина: нет сообщений для обработки из-за FloodWait

### 1.3. Проверка связи с дайджестом

**Анализ кода дайджеста**:

1. **`api/services/digest_service.py`**:
   - Метод `generate_channel_digest()` только **читает** посты из БД
   - Не влияет на парсинг или сохранение постов
   - Проверка доступа через `user_channel` JOIN - не блокирует парсинг

2. **`api/routers/channels.py`**:
   - Endpoint `/users/{user_id}/channels/{channel_id}/digest` только генерирует дайджест
   - Не влияет на парсинг

**Вывод**: Дайджест **не влияет** на парсинг постов. Проблема в FloodWait.

---

## 2. Причина проблемы

### 2.1. Основная причина: FloodWait

**Проблема**: 
- Telegram API ограничил запросы из-за слишком частых запросов `ResolveUsernameRequest`
- FloodWait: 9574 секунд (~2.7 часа)
- Парсер не может получить entity канала
- `messages_processed = 0` (нет сообщений для обработки)
- Посты не сохраняются в БД

**Проблемные каналы**:
- `fffworks` (674682b4-3afa-48fd-b5dd-fd66f79151cb)
- `jun_hi` (619c6954-f162-499e-8201-d6f861c4a3d0)
- `designsniper` (35d8421a-ebe8-4a64-8912-f299a565b287)
- `naebnet` (1a81433d-351a-43bb-9974-f64e1c3bc1a6)

### 2.2. Почему кажется, что проблема связана с дайджестом?

**Вероятная причина**:
1. Дайджест был доработан сегодня
2. Пользователь заметил отсутствие постов после доработок
3. Но на самом деле проблема в FloodWait, который начался раньше

**Проверка**: FloodWait начался в 17:07 UTC (из предыдущих логов), а не после доработок дайджеста.

## 3. Решения

### 3.1. Немедленные действия

1. **Дождаться окончания FloodWait**:
   - FloodWait: 9574 секунд (~2.7 часа)
   - Текущее время: 2026-01-12 20:40 UTC
   - Осталось ждать: ~2.5 часа (FloodWait еще активен)

2. **Проверить доступность каналов**:
   - Проверить каналы вручную через Telegram
   - Убедиться, что каналы не удалены и доступны

3. **Обновить tg_channel_id** (если нужно):
   ```bash
   python3 telethon-ingest/scripts/backfill_tg_channel_id.py
   ```

### 3.2. Долгосрочные улучшения

1. **Улучшить обработку FloodWait**:
   - ✅ Уже исправлено: добавлена обработка FloodWaitError для ResolveUsernameRequest
   - ✅ Уже исправлено: увеличен MAX_FLOOD_WAIT до 300 секунд
   - ⏳ Требуется: дождаться окончания текущего FloodWait

2. **Улучшить entity cache**:
   - Обновлять entity cache перед парсингом
   - Проверять актуальность entity

3. **Добавить проверку доступности каналов**:
   - Автоматическая проверка перед парсингом
   - Обновление `is_active` для недоступных каналов

## 4. Проверка связи с дайджестом

### 4.1. Анализ изменений в дайджесте

**Изменения в `api/services/digest_service.py`**:
- Метод `generate_channel_digest()` - только чтение постов
- Метод `_collect_channel_posts_for_digest()` - только SELECT из БД
- Не влияет на парсинг или сохранение постов

**Изменения в `api/routers/channels.py`**:
- Endpoint `/users/{user_id}/channels/{channel_id}/digest` - только генерация дайджеста
- Проверка доступа через `user_channel` JOIN - не блокирует парсинг
- Не влияет на парсинг или сохранение постов

**Вывод**: Дайджест **не влияет** на парсинг постов.

### 4.2. Возможные косвенные влияния

**Гипотеза 1**: Дайджест создает нагрузку на БД, что замедляет парсинг
- **Проверка**: Дайджест только читает посты, не блокирует INSERT
- **Вывод**: Маловероятно

**Гипотеза 2**: Дайджест блокирует доступ к каналам
- **Проверка**: Дайджест не использует Telegram API для получения entity
- **Вывод**: Невозможно

**Гипотеза 3**: Дайджест изменяет состояние каналов в БД
- **Проверка**: Дайджест только читает, не изменяет `channels` или `user_channel`
- **Вывод**: Невозможно

**Итоговый вывод**: Дайджест **не влияет** на парсинг постов. Проблема в FloodWait.

# Исправление алерта VisionWorkerNotProcessing

**Дата**: 2025-12-03  
**Проблема**: Алерт срабатывает, но worker на самом деле работает

---

## 📊 Анализ

### Факты

1. **Vision worker работает**:
   - VisionAnalysisTask запущен и обрабатывает события
   - В логах есть записи "Vision event processed"
   - Lag небольшой (4 сообщения из 6981)

2. **Метрика не экспортируется**:
   - `vision_worker_processed_total` не появляется в Prometheus
   - Возможно, метрика является MockMetric из-за дублирования

3. **Алерт срабатывает неправильно**:
   - Условие: `rate(vision_worker_processed_total[5m]) == 0`
   - Но метрика отсутствует, поэтому rate = 0
   - Worker на самом деле работает

---

## 🔧 Решения

### Вариант 1: Исправить экспорт метрики

Проблема может быть в том, что метрика создается как MockMetric. Нужно:

1. Проверить, что метрика не MockMetric:
   ```python
   from worker.tasks.vision_analysis_task import vision_worker_processed_total
   print(type(vision_worker_processed_total))  # Должно быть Counter, не MockMetric
   ```

2. Если MockMetric - найти причину:
   - Проверить логи на "Metric exists but could not retrieve from REGISTRY"
   - Проверить дублирование метрик при перезапуске worker

3. Исправить регистрацию метрики:
   - Убедиться, что метрика регистрируется в Prometheus registry
   - Проверить, что метрика экспортируется через /metrics endpoint

### Вариант 2: Изменить условие алерта

Если метрика не может быть исправлена, изменить алерт на проверку других метрик:

```yaml
- alert: VisionWorkerNotProcessing
  expr: |
    rate(vision_events_total[5m]) == 0
    and
    sum(stream_pending_size{stream=~"stream:posts:vision"}) > 10
  for: 10m
```

Или использовать другую метрику, которая точно экспортируется.

### Вариант 3: Использовать альтернативные метрики

Проверить наличие других метрик vision:
- `vision_events_total` - может быть доступна
- `vision_analysis_duration_seconds` - может быть доступна
- `vision_media_total` - может быть доступна

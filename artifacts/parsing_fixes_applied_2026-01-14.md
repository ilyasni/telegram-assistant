# Примененные исправления для проблемы парсинга

**Дата**: 2026-01-14 23:35  
**Context7**: Исправления на основе анализа предложений

---

## Проблема

**Симптомы**:
- Все парсинги показывают `messages_processed: 0`
- Множество предупреждений "No available sessions after rate limiting"
- В БД нет новых постов за последний час

**Причина**:
- `PARSER_MAX_CONCURRENCY=4` - слишком мало для 49 каналов
- Только 2 сессии доступны (389326685, 139883458), collector (8124731874) не найден
- Нет ограничения глобального параллелизма каналов
- Нет детального логирования acquire/release семафоров

---

## Примененные исправления

### 1. Добавлено детальное логирование acquire/release семафоров

**Файл**: `telethon-ingest/services/session_rate_limiter.py`

**Изменения**:
- Добавлено логирование `lease_try` с `in_use`, `max_concurrent`, `semaphore_value`
- Добавлено логирование `lease_acquired` с `wait_time`, `in_use_after`
- Добавлено логирование `lease_released` с `in_use_before`, `in_use_after`

**Цель**: Позволить отслеживать утечки семафоров и состояние занятости сессий

### 2. Улучшено логирование "No available sessions"

**Файл**: `telethon-ingest/services/channel_parser.py:858`

**Изменения**:
- Добавлено детальное логирование с `healthy_sessions_count`, `max_fallback_sessions`, `session_pool_size`

**Цель**: Понять, почему сессии недоступны (все в FloodWait, все заняты, недостаточно сессий)

### 3. Ограничен глобальный параллелизм каналов

**Файл**: `telethon-ingest/tasks/parse_all_channels_task.py:1058`

**Изменения**:
- Добавлен расчет `global_channel_concurrency = min(15, max_concurrency * 3)`
- Добавлено логирование глобального лимита
- Ограничен размер батча до `global_channel_concurrency`

**Цель**: Предотвратить стадный эффект - все 49 каналов одновременно пытаются получить сессию

### 4. Увеличен max_concurrent_per_session

**Файл**: `telethon-ingest/services/session_rate_limiter.py:65`

**Изменения**:
- `max_concurrent_per_session: int = 3` → `max_concurrent_per_session: int = 10`

**Цель**: Увеличить пропускную способность каждой сессии

### 5. Увеличен timeout для acquire_session

**Файл**: `telethon-ingest/services/channel_parser.py:818`

**Изменения**:
- `timeout=2.0` → `timeout=10.0`

**Цель**: Дать больше времени для получения семафора при параллельной обработке

1. ✅ Детальное логирование покажет состояние семафоров
2. ✅ Ограничение глобального параллелизма предотвратит стадный эффект

## Проверка

После перезапуска контейнера проверить:
1. Логи `lease_try`, `lease_acquired`, `lease_released` - симметричность
2. Логи `no_available_sessions` - причины недоступности
3. Логи `Global channel concurrency limit` - установленный лимит
4. Увеличение `messages_processed` в `CHANNEL_PARSE_END`
5. Появление новых постов в БД

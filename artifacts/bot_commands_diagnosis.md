# Диагностика проблемы с командами бота

**Дата**: 2026-01-12  
**Context7**: Детальное логирование для диагностики

## Проблема

Команды бота (`/menu`, `/help` и другие) не работают или работают с ошибками:
- Команда `/menu` отправляет сообщение, но затем появляется ошибка
- Команды не реагируют на запросы пользователя

## Наблюдения из логов

### 1. Webhook обрабатывается, но команды не логируются

- Webhook запросы приходят: `POST /tg/bot/webhook`
- Webhook возвращает 200 OK
- Но нет логов "Processing message update" или "Menu command received"
- Это означает, что либо:
  - Логирование не срабатывает (уровень логирования)
  - Команда не доходит до обработчика
  - Update не содержит message

### 2. Долгая обработка webhook

- Некоторые webhook обрабатываются очень долго: 61 секунда, 121 секунда
- Это указывает на зависание при отправке сообщений в Telegram API
- Ошибки: `ServerDisconnectedError` и `Request timeout error`

### 3. Ошибки при отправке сообщений

- `ServerDisconnectedError: Server disconnected` - Telegram API отключается
- `Request timeout error` - таймаут при отправке сообщения
- Это происходит при попытке отправить ответ на команду

## Исправления

### ✅ Изменен уровень логирования

**Файл**: `api/bot/webhook.py`

- Изменено с `logger.debug` на `logger.info` для видимости логов
- Добавлено логирование всех сообщений, не только текстовых

### ✅ Улучшена обработка ошибок

**Файл**: `api/bot/handlers/base.py`

- Добавлен `return` после успешной отправки меню
- Улучшена обработка ошибок в `/help`
- Добавлено детальное логирование

### ✅ Добавлено логирование в webhook handler

**Файл**: `api/bot/webhook.py`

- Логирование типа update (message, callback_query, other)
- Логирование текста сообщения или callback_data
- Отдельная обработка ошибок при `dp.feed_update`

## Следующие шаги

1. **Попросить пользователя отправить команду `/menu` снова**
2. **Проверить логи** на наличие:
   - `Processing message update` - update получен
   - `Menu command received` - команда обработана
   - `Menu sent successfully` - сообщение отправлено
   - Или ошибки с деталями

## Команды для проверки

```bash
# Проверить логи после нового запроса
docker compose logs api --tail 500 | grep -E "(Processing message update|Menu command|Error)" -A 10

# Проверить время обработки webhook
docker compose logs api --tail 200 | grep "RES.*webhook"

# Проверить статус API
docker compose ps api --format "{{.Status}}"
```

## Возможные причины

1. **Проблемы с сетью** - Telegram API недоступен или медленно отвечает
2. **Проблемы с таймаутами** - aiogram использует дефолтные таймауты (30 секунд)
3. **Проблемы с логированием** - уровень логирования может быть выше INFO
4. **Проблемы с обработчиками** - команды не регистрируются правильно

## Рекомендации

1. Проверить логи после нового запроса команды
2. Если логи не появляются - проверить настройки логирования
3. Если команды не обрабатываются - проверить регистрацию роутеров
4. Если таймауты - настроить таймауты для aiogram Bot

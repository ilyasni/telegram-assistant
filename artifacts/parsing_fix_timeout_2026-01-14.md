# Исправление проблемы парсинга - увеличение timeout для SessionRateLimiter

**Дата**: 2026-01-14 23:25  
**Context7**: Исправление проблемы недоступности сессий из-за слишком короткого timeout

---

## Проблема

**Симптомы**:
- ❌ Все парсинги показывают `messages_processed: 0`
- ❌ 246 предупреждений "No available sessions after rate limiting" за 30 минут
- ❌ В БД нет новых постов за последний час

**Причина**:
- `SessionRateLimiter.acquire_session()` вызывается с `timeout=2.0` секунды
- При параллельной обработке 49 каналов семафоры (max 3 на сессию) быстро заняты
- Запросы не успевают получить сессию за 2 секунды и пропускаются

---

## Исправление

**Изменение**: Увеличен timeout с 2.0 до 10.0 секунд в `channel_parser.py:816`

**Код до**:
```python
if not await self.session_rate_limiter.acquire_session(account_id, timeout=2.0):
```

**Код после**:
```python
# Context7: Увеличиваем timeout до 10 секунд для параллельной обработки множества каналов
# При обработке 49 каналов параллельно семафоры могут быть заняты, но освободятся
if not await self.session_rate_limiter.acquire_session(account_id, timeout=10.0):
```

---

## Ожидаемый результат

1. ✅ Запросы будут ждать до 10 секунд для получения сессии
2. ✅ При освобождении семафоров парсинг начнет работать
3. ✅ Новые посты начнут появляться в БД

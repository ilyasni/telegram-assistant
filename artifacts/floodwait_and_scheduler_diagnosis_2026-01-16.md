## Причина проблемы

### Цепочка событий:

1. **Глобальный FloodWait установлен** для сессии collector (8124731874)
   - Когда: примерно ~4.3 часа назад (около 02:00 UTC)
   - Причина: FloodWait > 60 секунд привел к активации circuit breaker
   - Время блокировки: ~15582 секунд (~4.3 часа)

2. **Все каналы используют collector**
   - В коде нет использования других сессий
   - Даже если `preferred_account_id` не установлен, используется collector

3. **Scheduler тики пропускают все каналы**
   - Тик запускается каждые 5 минут
   - Все каналы проверяются на глобальный FloodWait
   - Все пропускаются с `"status": "skipped", "reason": "global_floodwait"`
   - Тик завершается за < 1 секунду (0.855 сек)

4. **Результат**: Никакие каналы не парсятся → новых постов нет

## Решения

### Краткосрочное (немедленно)

**Вариант 1: Дождаться автоматической разблокировки**
- Время: ~4.32 часа (до 11:00 UTC)
- Действие: Ничего не делать, дождаться истечения TTL в Redis
- Риск: Низкий, но парсинг будет простаивать еще 4+ часа

**Вариант 2: Снять блокировку вручную (если FloodWait был ложным)**
```bash
# Удалить ключ из Redis
docker compose exec redis redis-cli DEL "tg:floodwait_until:8124731874"
```
- Риск: Средний - если FloodWait реальный, Telegram может снова заблокировать
- Проверка: После снятия проверить, что парсинг возобновился

**Вариант 3: Использовать другие сессии**
- Проблема: Код не использует другие сессии из TelegramClientManager
- Решение: Требуется изменение кода для использования других сессий, когда collector заблокирован

### Долгосрочное (архитектурное)

1. **Мульти-сессионная архитектура**
   - Использовать другие сессии из пула, когда collector в FloodWait
   - Реализовать автоматическое переключение между сессиями

2. **Улучшенный circuit breaker**
   - Более гибкая логика: не блокировать все каналы, если доступны другие сессии
   - Использовать `get_healthy_sessions()` из FloodWaitManager

3. **Мониторинг и алерты**
   - Алерт на глобальный FloodWait > 1 часа
   - Алерт на отсутствие новых постов > 6 часов
   - Метрика: время до разблокировки глобального FloodWait

## Impact / Rollback

### Impact

**Текущее состояние**:
- Парсинг полностью заблокирован
- Новые посты не появляются
- Каналы не обновляются

**После снятия блокировки**:
- Парсинг возобновится автоматически
- Каналы начнут обновляться с следующего тика scheduler'а
- Новые посты появятся в течение 5-10 минут после разблокировки

### Rollback

Если снятие блокировки вручную вызвало проблемы:

1. **Восстановить блокировку** (если нужно):
   ```bash
   # Установить блокировку на оставшееся время (примерно 4 часа)
   docker compose exec redis redis-cli SETEX "tg:floodwait_until:8124731874" 14400 "1768561217.4067798"
   ```

2. **Проверить логи**:
   ```bash
   docker compose logs --since 5m telethon-ingest | grep -i floodwait
   ```

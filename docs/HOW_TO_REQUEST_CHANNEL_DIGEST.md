# Как запросить дайджест по каналу через Telegram бота

**Дата**: 2025-12-19  
**Context7**: Соответствует best practices для UX и обработки ошибок

## 📱 Инструкция для пользователя

### Способ 1: Через команду `/my_channels`

1. **Откройте бота** в Telegram
2. **Отправьте команду**: `/my_channels`
3. **Выберите канал** из списка (нажмите на кнопку с названием канала)
4. **Нажмите кнопку** "📰 Дайджест"
5. **Выберите период**:
   - 📅 **День** — дайджест за последние 24 часа
   - 📅 **Неделя** — дайджест за последние 7 дней
   - 📅 **Месяц** — дайджест за последние 30 дней
6. **Получите результат** — бот отправит дайджест с:
   - Executive Summary (краткое резюме)
   - Топ-10 важных постов
   - Тренды и повторяющиеся темы

### Способ 2: Через главное меню

1. **Откройте бота** в Telegram
2. **Отправьте команду**: `/start` (или используйте кнопку "🔙 Главное меню")
3. **Нажмите кнопку** "📊 Мои каналы"
4. **Выберите канал** из списка
5. **Нажмите кнопку** "📰 Дайджест"
6. **Выберите период** (День/Неделя/Месяц)
7. **Получите результат**

## 🔧 Технические детали (Context7)

### UX Flow

```
/my_channels или menu:channels
  ↓
channel:view:{channel_id}
  ↓
channel:digest:{channel_id}
  ↓
[Выбор периода]
  ↓
channel:digest:{channel_id}:{period}
  ↓
_generate_channel_digest()
  ↓
POST /api/users/{user_id}/channels/{channel_id}/digest?period={period}
  ↓
[Показ результата или ошибки]
```

### Обработка ошибок (Context7 Best Practices)

**Все ошибки логируются с контекстом:**
- `tenant_id` — для multi-tenant изоляции
- `user_id` — для трассировки пользователя
- `channel_id` — для диагностики
- `period` — для анализа производительности

**Типы ошибок и их обработка:**

1. **Пользователь не найден**
   - Сообщение: "❌ Пользователь не найден. Используйте /start"
   - Логирование: ERROR с контекстом

2. **Канал не найден или нет доступа**
   - Сообщение: "❌ Канал не найден или нет доступа"
   - Логирование: WARNING с контекстом

3. **Нет постов за период**
   - Сообщение: "📭 В канале не было постов за выбранный период"
   - Логирование: INFO с контекстом

4. **Превышено время ожидания (только для месяца)**
   - Сообщение: "⏳ Генерация дайджеста занимает больше времени. Пожалуйста, подождите..."
   - Логирование: INFO с контекстом
   - TODO: В будущем будет async job с уведомлением

5. **Ошибка API**
   - Сообщение: "❌ Произошла ошибка при генерации дайджеста. Попробуйте позже."
   - Логирование: ERROR с полным traceback

6. **Ошибка сети**
   - Сообщение: "❌ Ошибка подключения к серверу. Проверьте соединение."
   - Логирование: ERROR с контекстом

### Формат ответа

**Дайджест разбивается на части**, если превышает лимит Telegram (4096 символов):
- Каждая часть отправляется отдельным сообщением
- Сохраняется структура (Executive Summary, Топ-посты, Тренды)

**Эмодзи для визуального разделения:**
- 📝 Executive Summary
- 🔥 Топ-10 важных постов
- 📈 Тренды

## 💡 Советы по использованию

1. **День** — быстрая генерация (< 30 сек), подходит для ежедневных обзоров
2. **Неделя** — средняя генерация (< 60 сек), подходит для еженедельных обзоров
3. **Месяц** — долгая генерация (может занять до 2-3 минут), подходит для глубокого анализа

**Рекомендации:**
- Используйте "День" или "Неделя" для быстрых обзоров
- Используйте "Месяц" для глубокого анализа трендов
- Дайджесты кешируются, повторный запрос будет быстрее

## 🔍 Отладка (для разработчиков)

### Проверка логов

```bash
# Логи бота
docker logs bot | grep "channel digest"

# Логи API
docker logs api | grep "channel_digest"

# Метрики Prometheus
curl http://localhost:8000/metrics | grep channel_digest
```

### Проверка кеша

```bash
# Redis кеш (ключ: channel_digest:{tenant_id}:{user_id}:{channel_id}:{period}:{date})
redis-cli KEYS "channel_digest:*"
```

### Проверка БД

```sql
-- История дайджестов
SELECT * FROM digest_history 
WHERE user_id = '...' 
ORDER BY digest_date DESC 
LIMIT 10;
```

## 📊 Метрики (Context7)

Все операции отслеживаются через Prometheus:

- `channel_digest_generation_total{tenant_id, period}` — счетчик запросов
- `channel_digest_generation_duration_seconds{tenant_id, period}` — время генерации
- `channel_digest_posts_count{tenant_id, period}` — количество постов
- `channel_digest_context_tokens{tenant_id, period}` — размер контекста
- `channel_digest_cache_hits_total{tenant_id, period}` — попадания в кеш
